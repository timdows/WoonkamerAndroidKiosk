WoonkamerKiosk

Kotlin Android launcher for Spotify and Samsung Phone, with guarded Device Owner
and Lock Task preparation. Requires Android 9 or newer; targets Android 16.

Build variants
- debug/release: kiosk activation disabled.
- kioskTrial: explicitly enabled supervised activation; test-only APK.
  Installation never starts Lock Task automatically.

Administrator access uses a separate 6-12 digit PIN, expires after
30 seconds and is dismissed when leaving the app. A supervised trial requires
Device Owner, a configured administrator PIN, an unlocked device, enabled required apps, Samsung Phone as
default dialer, and explicit confirmation of call testing and recovery access.
Stopping restores saved Lock Task policy. Device Owner remains installed.

Notifications, Home, system information and power menu are retained
in Lock Task. Keyguard is omitted while locked to the kiosk, preserving the device
pattern outside the kiosk. A foreground service holds a screen wake lock across
allowed apps, releases it on exit and stops when Lock Task ends. The power button,
call proximity behavior, battery exhaustion and OS restrictions can still turn
the screen off. Continuous display use consumes power; moderate brightness and
a charger are recommended. Incoming-call behavior must be validated on the target firmware.
Package allowlisting does not restrict every screen within each allowed app.
Automatic activation after reboot is intentionally not implemented.

Build with the Gradle wrapper and a configured Android SDK:
  gradlew assembleDebug assembleKioskTrial testDebugUnitTest lintDebug lintKioskTrial
Additional variant tests:
  gradlew testKioskTrialUnitTest testReleaseUnitTest -Pandroid.onlyEnableUnitTestForTheTestedBuildType=false

The kioskTrial APK requires adb install -t. Only provision a test-only Device
Owner after reviewing recovery access and backups. The ADB development recovery
command is dpm remove-active-admin with this app's KioskAdminReceiver component.
Do not replace a registered test-only owner with a non-test-only production
build without reviewing the recovery implications.

Instrumentation runners are emulator-only and excluded from application APKs.
The Lock Task fixture uses the launcher only; it does not simulate real phone
or Spotify behavior. Select it with the kioskTestRunner Gradle property set to
nl.woonkamer.kiosk.LockTaskInstrumentation. Device Owner setup and credentials
are external test prerequisites; no fixed test credential is included here.

SDK paths, IDE state, APKs, build reports, private notes and captured device
screenshots are excluded from version control.

Administrator PINs use salted PBKDF2 and a device-bound Android Keystore HMAC; no
plaintext PIN is stored or backed up. Five failed attempts impose a persisted
30-second delay. First-time setup requires the existing device credential when
one exists. Lost credentials require the ADB development recovery route; no
default or remote PIN bypass exists. New credentials are entered on-device only.


The home screen shows the family-phone title, three launch cards and a large
24-hour clock at the bottom. There is no greeting or other surrounding copy.
Mobile data and Wi-Fi settings are managed through Android by the administrator;
this application does not monitor connectivity or suspend Spotify on Wi-Fi loss.

Administrator entry is hidden: tap the clock ten times to open PIN verification.
There is no visible administrator button, counter, hint or feedback. The tap
sequence resets when leaving the activity or opening another app.

Outgoing calls also require the Android Telecom system package in the Lock Task
allowlist. Its intermediate call activities are distinct from Samsung Phone and
the in-call interface. Messages and video calling are not part of the allowlist.

Home Assistant is available beside Phone in the second row; Spotify remains a
full-width card above, with the clock below. The installed full or minimal
Companion app is detected and included in the Lock Task allowlist on activation.
If neither flavor is installed, its card explains setup without blocking the
rest of the kiosk. Configure the Companion app outside kiosk mode first. No
server addresses or credentials are stored in this launcher.
